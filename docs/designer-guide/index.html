Appmilla · for designers

From Claude Design to a clickable prototype

Eight steps, done mostly in plain words to Claude. You never need to touch code, Git or settings: Claude does that and tells you what changed on screen.

  • 1New repository
  • 2Open in Claude
  • 3Bring the design
  • 4Build
  • 5Click through
  • 6Change things
  • 7Share
  • 8Sign-off

Before your first prototype

  • You're a member of the Appmilla organisation on GitHub.
  • You can sign in to claude.ai/code, on your phone or computer.
  • Rich has set up Claude Code's Default environment so sharing with clients works. You'll keep it in step 2.
  1. 1

    Make a new repository from the template

    Each prototype gets its own private home on GitHub, copied from Appmilla's starter.

    1. Open github.com/Appmilla/prototype-starter.
    2. Tap Use this template, then Create a new repository.
    1. Owner: Appmilla. Name: the client and the product, like acme-dashboard-prototype.
    2. Choose Private. Client work is never public.
    3. Tap Create repository.
  2. 2

    Open it in Claude Code

    This is where you'll talk to Claude about the prototype from now on.

    1. Go to claude.ai/code.
    2. Pick your new repository, for example Appmilla/acme-dashboard-prototype.
    3. Leave the environment on Default, and pick the model Opus 5.5 on High.
  3. 3

    Bring the design over

    Claude needs the design you made: the screens, components and styles. Use whichever way suits you.

    Save it straight to the repository

    In the chat where you made the design, ask Claude to save the design files to your new repository.

    Or export it and attach it

    Open the design, tap Share, then Export, and download the ZIP.

    In step 4, tap + next to the message box and attach the .zip before you send.

  4. 4

    Ask Claude to build it

    Claude reads the design, builds the first few screens so you can click something quickly, then builds the rest.

    Say this
    Build the clickable prototype from the design.

    A first build takes a while. You can leave it running and come back; Claude carries on.

  5. 5

    Click through every screen

    The Screens page lists every screen, and each one in its four other states, so nothing gets missed.

    Open the link Claude gives you. If it doesn't open (the preview only runs inside Claude's session when you use Claude Code on the web or on a phone), ask Claude to share it with you: you'll get a private link that works anywhere and that only the Appmilla team can open (step 7).

    • Empty: nothing to show yet. Loading: waiting for data. Error: something failed. Not allowed: this person can't see it.
    • All the data is made up. Ask Claude to reset the demo data to put it back as it started.
  6. 6

    Ask for changes in plain words

    Say what you want to see. Claude changes it and tells you what's different on screen.

    Add a settings screen with notification preferences.New screen
    The Save button should go back to the list.Where a button goes
    Show the shift name on each alert card.What a screen shows
    Only supervisors should see the reports screen.Who can see it
    Sign me in as a supervisor.See it as someone else
  7. 7

    Share it with the client

    You get a private link. Only the people you name, and the Appmilla team, can open it.

    Say this
    Share this with the client.

    When the client opens the link, they type their email in the Email box, tap Send login code, then enter the code that's emailed to them. No account, no password.

    Next they see the prototype's own sign-in. It's part of the design, not real security: any of the made-up usernames shown on it works, with any password.

    • The client sees the version you shared. Your later changes reach them when you share again.
    • To add or remove someone: “Let jo@acme.example see it too”, “Stop sam@acme.example seeing it”.
    • When the project's finished: “Take the prototype offline.”
  8. 8

    Get it signed off

    Claude checks every screen is there and draws all its states, and lists what changed since the client last signed off.

    Before the client looks
    Is it ready for sign-off?
    When they've approved it
    The client signed it off.

    After sign-off the engineering team builds the real product from the prototype's pages.

If something's not right

  • Say what you see, in your own words: “The alerts screen is blank on my phone.”
  • If Claude says sharing isn't switched on, the environment isn't set up for sharing yet. Ask Rich.
  • Lost the link? Ask “What's the link for the client?”
